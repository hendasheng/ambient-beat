# PingPong Topdown 动画状态机说明

## 1. 目的

这份文档用于把需求说明进一步转成实现层可直接使用的运动状态定义。当前 `0.1` 已按这套状态机进入基础实现，文档继续作为后续调整一拍、一回合和连续循环的约束来源。

## 2. 系统总原则

整个动画系统不应被理解为“一个球不断随机移动”，而应被理解为“回合状态不断推进”。

系统最小单位不是像素位置，而是 `一次合法回球`。

每次合法回球都必须满足：

1. 出球
2. 过网
3. 对方半台落台
4. 弹起
5. 对方回击

如果某一段缺少其中关键阶段，视觉上就会失去真实乒乓球语义。

## 3. 顶层结构

建议将连续动画拆成以下三层：

- 回合层：决定当前是从左打向右，还是从右打向左
- 单拍层：定义一拍内部的时序推进
- 表现层：根据当前时序输出球、投影、轨迹线和落点提示

这三层的职责必须分开：

- 回合层负责逻辑顺序
- 单拍层负责时间推进
- 表现层负责画面结果

## 4. 单拍状态定义

单拍建议拆成 5 个状态。

### 4.1 `strike`

含义：

- 当前一方完成击球
- 新的一拍开始成立

作用：

- 确定本拍起点
- 确定目标落点
- 确定本拍力量和方向类型
- 初始化本拍轨迹线

画面表现：

- 球从击球起点开始离开
- 投影开始与球产生分离
- 轨迹线开始建立，但不是拖尾

### 4.2 `flight`

含义：

- 球正在飞向对方半台

作用：

- 推进跨台运动
- 体现击球方向、速度和力量

画面表现：

- 球越过中线
- 轨迹线描述本拍主路径
- 球与投影保持飞行阶段的分离关系

约束：

- 这个阶段不允许提前反向
- 这个阶段结束条件必须是“到达对方半台落点”

### 4.3 `bounce_contact`

含义：

- 球与台面发生触台接触

作用：

- 明确告诉用户“球已经先落台了”
- 将飞行段和弹起段断开

画面表现：

- 球与投影接近或短暂重合
- 落点提示瞬时出现
- 轨迹节奏发生一次清楚但克制的转折

约束：

- 这是一个很短的状态
- 不能省略

### 4.4 `bounce_rise`

含义：

- 球在触台后弹起，进入可被回击的窗口

作用：

- 提供回击前的缓冲阶段
- 让“触台后再回击”的逻辑可视化

画面表现：

- 球与投影再次拉开
- 球继续在平面上短距离推进
- 轨迹线进入落台后的短段延续

约束：

- 这个状态必须发生在回击之前
- 持续时间不能长到像第二次长飞行
- 持续时间也不能短到看不出弹起

### 4.5 `return_strike`

含义：

- 对方在弹起阶段内完成回击

作用：

- 结束本拍
- 生成下一拍的起点条件

画面表现：

- 运动方向正式反转
- 下一拍轨迹开始接管
- 上一拍轨迹进入淡出

约束：

- 不能直接把它做成瞬移切换
- 需要让用户感知这是“被打回来”，不是“自动折返”

## 5. 状态切换关系

建议的基础切换顺序为：

`strike -> flight -> bounce_contact -> bounce_rise -> return_strike`

然后下一拍以相反方向重新进入：

`strike -> flight -> bounce_contact -> bounce_rise -> return_strike`

整个系统本质上是在左右两侧轮流重复该链条。

## 6. 左右回合模型

建议每一拍都带一个 `direction`：

- `left_to_right`
- `right_to_left`

该方向用于决定：

- 击球起点在哪一侧
- 目标落点在哪一侧
- 轨迹线主方向
- 投影偏移的视觉一致性

方向反转只能发生在 `return_strike` 完成之后。

## 7. 单拍输入参数

每一拍开始时，需要先生成一组拍内参数，后续状态只消费它们，不应在拍中频繁改写。

建议参数包括：

- `direction`：左右方向
- `power`：击球力量
- `shotType`：击球类型
- `targetX`：目标落点横向位置
- `targetY`：目标落点纵向位置
- `arcBias`：路径弯曲倾向
- `speedProfile`：本拍速度曲线类型
- `bounceHeight`：弹起高度倾向
- `postBounceDrift`：触台后短段位移倾向

## 8. 击球类型建议

首版不需要很多类型，但建议至少保留以下抽象类别：

- `drive`：平直稳定回球
- `cross`：带明显斜线的回球
- `change_line`：从一侧突然改向另一侧
- `short_push`：较短、较收的控制球
- `fast_attack`：速度更强、路径更直接的进攻球

这些类型不是为了模拟专业技战术细节，而是为了让回合看起来不单调。

## 9. 落点生成约束

落点不能完全随机，应遵循可读的分布规则。

要求：

- 落点必须在对方半台之内
- 长短球需要有不同的深度区间
- 斜线球需要体现明显横向偏移
- 连续几拍不应总落在完全同一区域

建议做法：

- 先按击球类型决定落点区域
- 再在区域内部做受控随机

## 10. 速度与时间规则

时间规则要服务于“回合可读”，而不是纯平滑。

建议将单拍时间拆成占比控制：

- `strike`：很短
- `flight`：最长
- `bounce_contact`：极短
- `bounce_rise`：短
- `return_strike`：短

总体原则：

- 飞行段负责跨台路径阅读
- 触台段负责事件确认
- 弹起段负责回击合法性

如果飞行过短，路径读不清；如果弹起过短，回合逻辑读不清。

## 11. 球与投影的状态映射

球和投影的关系不应单独随机，而应严格随状态变化。

### `strike`

- 球与投影开始分离
- 分离速度较快

### `flight`

- 保持中等或较明显分离
- 分离程度可随力量提升

### `bounce_contact`

- 快速收拢到最小距离
- 形成触台确认

### `bounce_rise`

- 再次拉开
- 但不必比主飞行段更夸张

### `return_strike`

- 进入下一拍前重新建立新的分离方向和节奏

## 12. 轨迹线的状态映射

轨迹线应随单拍状态分段组织，而不是一条从头跟到尾的尾迹。

建议规则：

- `strike`：启动当前拍轨迹
- `flight`：生成本拍主线段
- `bounce_contact`：在落点处形成清晰转折或断点提示
- `bounce_rise`：增加一小段落台后延续线
- `return_strike`：当前拍轨迹转入淡出，下一拍轨迹创建

这样做的目的，是让用户感知到“本拍已经完成，下一拍已经开始”。

## 13. 落点提示的状态映射

落点提示只应该绑定在 `bounce_contact`。

要求：

- 只出现一次
- 时长很短
- 不影响球与轨迹的主阅读

如果后续需要更克制的版本，可以先保留接口，再决定是否默认开启。

## 14. 连续循环的节奏策略

整个系统不能每拍都同一种节奏，否则很快会像模板循环。

建议节奏策略：

- 多数时间保持稳定对拉
- 少量拍子插入斜线或变线
- 偶尔提升力量形成快攻感
- 快与慢之间要有缓冲，避免突兀

可将连续回合理解为：

- `基础稳定段`
- `变化插入段`
- `重新回稳段`

## 15. 首版实现优先级

首版真正需要先做对的，不是复杂变化，而是顺序正确。

优先级建议如下：

1. 先跑通合法单拍状态链
2. 再做左右连续切换
3. 再加投影高度阅读
4. 再加轨迹线粗细和透明度差异
5. 最后再加落点类型和节奏变化

## 16. 验收问题清单

如果后续进入实现阶段，可以用这组问题直接检查状态机是否成立：

- 用户能否看出球是被一方打向另一方，而不是自己折返？
- 用户能否看出落台是独立事件？
- 用户能否看出回击发生在落台之后？
- 用户能否通过投影看出高度变化？
- 用户能否区分当前拍轨迹和上一拍残留？
- 用户会不会把轨迹误解成拖尾？

如果这些问题里有一项回答是否定的，就说明状态设计还需要继续调整。
